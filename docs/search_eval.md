## 5.1. Золотий набір (`eval/gold.jsonl`)
Усього **45** запитів: keyword: 14, paraphrase: 14, multihop: 12, no_answer: 5; без відповіді — **5**.
Релевантність розмічено на рівні розділів (`doc_id#section`), оцінки 2 — пряма відповідь, 1 — часткова.
Кандидати запитів і розмітку запропонувала LLM (див. `llm_log/`); попередні оцінки verdict у `eval/gold_review.xlsx` також поставила LLM (91 пара — ok), студентка переглянула таблицю й прийняла набір без змін (V3).

## 5.6. Вартість і затримка
- Усі моделі працюють локально на CPU: **вартість API = 0 $**, дані не передаються в зовнішні сервіси.
- Embedding-модель: 118 млн параметрів; reranker: 118 млн параметрів (`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`).
- Затримка: див. таблицю 5.3 (reranker додає приблизно 1144 мс на запит,
  бо cross-encoder обробляє 30 пар «запит–фрагмент»).

## 5.7. Висновок (вибір для ЛР 11)
Найвищий nDCG@10 — **`hybrid_rerank`** (0.769).
Для ЛР 11 обрано **`hybrid_rerank`**: він найкращий за всіма метриками (recall@5 0.777, MRR 0.819, nDCG@10 0.769), особливо на ключових словах (0.940) і багатокрокових запитах (0.554), а score cross-encoder дає змогу відсікати запити без відповіді.
- **Якість:** +0.071 nDCG@10 до `hybrid` і +0.128 до `dense`.
- **Затримка:** ≈1.2 с на запит на CPU (у 60+ разів повільніше за hybrid). Для RAG у ЛР 11 це прийнятно, бо генерація LLM однаково триває секунди; для інтерактивного пошуку можна зменшити топ-30 → топ-15 або використати GPU.
- **Вартість:** 0 $ (локальні моделі, ~236 млн параметрів разом, CPU).
- **Запасний варіант:** `hybrid` (18 мс, nDCG 0.698), якщо затримка стане критичною.
